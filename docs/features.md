# UI-фичи

Пользовательские функции веб-приложения букмекерской конторы Skam Bet, описанные на языке Gherkin
(Cucumber, `# language: ru`). Каждая фича автоматизирована UI-тестами на Selenium WebDriver,
исходные файлы лежат в `src/test/resources/features`, сценарии прецедентов к ним — в [scenarios.md](scenarios.md).

| № | Фича | Действующие лица | Тег | Сценариев | Файл |
|---|---|---|---|---|---|
| 1 | Регистрация пользователя | Гость | `@registration` | 9 | `01_registration.feature` |
| 2 | Авторизация пользователя | Пользователь | `@login` | 6 | `02_login.feature` |
| 3 | Просмотр линии событий | Гость, Пользователь | `@events` | 5 | `03_events_line.feature` |
| 4 | Пополнение баланса | Пользователь | `@deposit` | 9 | `04_deposit.feature` |
| 5 | Оформление ставки | Пользователь | `@bet` | 7 | `05_bet.feature` |
| | **Всего** | | | **36** | |

Запуск одной фичи: `gradlew test -Dcucumber.filter.tags=@bet`.

## 1. Регистрация пользователя

Создание личного кабинета: логин, email, дата рождения (только 18+), пароль и согласие с правилами. Все поля проверяются на сервере, ошибки выводятся под полями.

> Чтобы делать ставки на спортивные события,<br>
> как посетитель сайта букмекерской конторы,<br>
> я хочу создать личный кабинет

Сценарии:

1. Успешная регистрация нового пользователя
2. Регистрация с уже занятым логином
3. Регистрация с некорректными данными (6 примеров)
4. Регистрация без согласия с правилами

```gherkin
# language: ru
@registration
Функция: Регистрация пользователя
  Чтобы делать ставки на спортивные события,
  как посетитель сайта букмекерской конторы,
  я хочу создать личный кабинет

  Предыстория:
    Дано посетитель открыл страницу "Регистрация"

  Сценарий: Успешная регистрация нового пользователя
    Когда посетитель заполняет форму регистрации:
      | логин         | ivan_petrov      |
      | email         | ivan@example.com |
      | дата рождения | 15.03.1998       |
      | пароль        | secret123        |
      | повтор пароля | secret123        |
    И отмечает согласие с правилами
    И нажимает кнопку "Зарегистрироваться"
    Тогда открывается страница "Вход"
    И отображается сообщение "Регистрация прошла успешно. Войдите в личный кабинет"
    Когда пользователь входит с логином "ivan_petrov" и паролем "secret123"
    Тогда в шапке сайта отображается пользователь "ivan_petrov"
    И баланс пользователя равен "0.00 ₽"

  Сценарий: Регистрация с уже занятым логином
    Дано зарегистрирован пользователь "ivan_petrov" с паролем "secret123"
    Когда посетитель заполняет форму регистрации:
      | логин         | ivan_petrov       |
      | email         | other@example.com |
      | дата рождения | 15.03.1998        |
      | пароль        | secret123         |
      | повтор пароля | secret123         |
    И отмечает согласие с правилами
    И нажимает кнопку "Зарегистрироваться"
    Тогда отображается ошибка "Пользователь с таким логином уже существует"
    И посетитель остаётся на странице "Регистрация"

  Структура сценария: Регистрация с некорректными данными
    Когда посетитель заполняет форму регистрации:
      | логин         | <логин>         |
      | email         | <email>         |
      | дата рождения | <дата рождения> |
      | пароль        | <пароль>        |
      | повтор пароля | <повтор пароля> |
    И отмечает согласие с правилами
    И нажимает кнопку "Зарегистрироваться"
    Тогда отображается ошибка "<ошибка>"
    И посетитель остаётся на странице "Регистрация"

    Примеры:
      | логин       | email            | дата рождения | пароль    | повтор пароля | ошибка                                                                   |
      | iv          | ivan@example.com | 15.03.1998    | secret123 | secret123     | Логин должен содержать от 3 до 20 символов: латинские буквы, цифры или _ |
      | ivan_petrov | ivan.example.com | 15.03.1998    | secret123 | secret123     | Введите корректный email                                                 |
      | ivan_petrov | ivan@example.com | 1998-03-15    | secret123 | secret123     | Укажите дату рождения в формате ДД.ММ.ГГГГ                               |
      | ivan_petrov | ivan@example.com | 01.01.2015    | secret123 | secret123     | Регистрация доступна только лицам, достигшим 18 лет                      |
      | ivan_petrov | ivan@example.com | 15.03.1998    | 12345     | 12345         | Пароль должен содержать не менее 8 символов                              |
      | ivan_petrov | ivan@example.com | 15.03.1998    | secret123 | secret321     | Пароли не совпадают                                                      |

  Сценарий: Регистрация без согласия с правилами
    Когда посетитель заполняет форму регистрации:
      | логин         | ivan_petrov      |
      | email         | ivan@example.com |
      | дата рождения | 15.03.1998       |
      | пароль        | secret123        |
      | повтор пароля | secret123        |
    И нажимает кнопку "Зарегистрироваться"
    Тогда отображается ошибка "Необходимо принять правила букмекерской конторы"
    И посетитель остаётся на странице "Регистрация"
```

## 2. Авторизация пользователя

Вход по логину и паролю, выход из системы, перенаправление гостя на страницу входа при открытии закрытых разделов и возврат на запрошенную страницу после входа.

> Чтобы получить доступ к балансу и своим ставкам,<br>
> как зарегистрированный пользователь,<br>
> я хочу входить в личный кабинет и выходить из него

Сценарии:

1. Успешный вход в личный кабинет
2. Вход с неверным логином или паролем (3 примеров)
3. Выход из личного кабинета
4. Переход гостя на страницу, доступную только после входа

```gherkin
# language: ru
@login
Функция: Авторизация пользователя
  Чтобы получить доступ к балансу и своим ставкам,
  как зарегистрированный пользователь,
  я хочу входить в личный кабинет и выходить из него

  Предыстория:
    Дано зарегистрирован пользователь "ivan_petrov" с паролем "secret123" и балансом 2500 ₽

  Сценарий: Успешный вход в личный кабинет
    Дано посетитель открыл страницу "Вход"
    Когда пользователь входит с логином "ivan_petrov" и паролем "secret123"
    Тогда открывается страница "Линия"
    И в шапке сайта отображается пользователь "ivan_petrov"
    И баланс пользователя равен "2500.00 ₽"

  Структура сценария: Вход с неверным логином или паролем
    Дано посетитель открыл страницу "Вход"
    Когда пользователь входит с логином "<логин>" и паролем "<пароль>"
    Тогда открывается страница "Вход"
    И отображается ошибка "Неверный логин или пароль"
    И в шапке сайта отображается ссылка "Вход"

    Примеры:
      | логин       | пароль    |
      | ivan_petrov | wrongpass |
      | petr_ivanov | secret123 |
      | ivan_petrov |           |

  Сценарий: Выход из личного кабинета
    Дано пользователь вошёл в систему с логином "ivan_petrov" и паролем "secret123"
    Когда пользователь нажимает кнопку "Выйти"
    Тогда открывается страница "Вход"
    И отображается сообщение "Вы вышли из системы"
    И в шапке сайта отображается ссылка "Вход"

  Сценарий: Переход гостя на страницу, доступную только после входа
    Когда посетитель открывает страницу "Мои ставки" по прямой ссылке
    Тогда открывается страница "Вход"
    Когда пользователь входит с логином "ivan_petrov" и паролем "secret123"
    Тогда открывается страница "Мои ставки"
    И в шапке сайта отображается пользователь "ivan_petrov"
```

## 3. Просмотр линии событий

Список предстоящих матчей с коэффициентами П1 / X / П2, сортировка по времени начала, фильтр по виду спорта. Начавшиеся события скрыты, в видах спорта без ничьей коэффициент X не показывается.

> Чтобы выбрать событие для ставки,<br>
> как посетитель сайта,<br>
> я хочу видеть предстоящие матчи с коэффициентами и фильтровать их по виду спорта

Сценарии:

1. Гость видит предстоящие события в порядке их начала
2. Фильтрация событий по виду спорта
3. Сброс фильтра по виду спорта
4. Вид спорта, по которому нет событий
5. Начавшиеся события не отображаются в линии

```gherkin
# language: ru
@events
Функция: Просмотр линии событий
  Чтобы выбрать событие для ставки,
  как посетитель сайта,
  я хочу видеть предстоящие матчи с коэффициентами и фильтровать их по виду спорта

  Предыстория:
    Дано в линии есть события:
      | вид спорта | хозяева | гости     | П1   | X    | П2   | начало через, ч |
      | Футбол     | Спартак | ЦСКА      | 2.10 | 3.40 | 3.20 | 5               |
      | Хоккей     | СКА     | Ак Барс   | 1.95 | 4.10 | 3.05 | 2               |
      | Футбол     | Зенит   | Краснодар | 1.65 | 3.90 | 5.20 | 26              |
      | Баскетбол  | ЦСКА    | Зенит     | 1.40 | -    | 2.85 | 30              |

  Сценарий: Гость видит предстоящие события в порядке их начала
    Когда посетитель открывает страницу "Линия"
    Тогда в линии отображаются события в следующем порядке:
      | СКА — Ак Барс     |
      | Спартак — ЦСКА    |
      | Зенит — Краснодар |
      | ЦСКА — Зенит      |
    И для события "Спартак — ЦСКА" отображаются коэффициенты:
      | П1   | X    | П2   |
      | 2.10 | 3.40 | 3.20 |
    И для события "ЦСКА — Зенит" ставка на ничью недоступна

  Сценарий: Фильтрация событий по виду спорта
    Дано посетитель открыл страницу "Линия"
    Когда посетитель выбирает вид спорта "Футбол"
    Тогда в линии отображаются события в следующем порядке:
      | Спартак — ЦСКА    |
      | Зенит — Краснодар |
    И вкладка "Футбол" выделена как активная

  Сценарий: Сброс фильтра по виду спорта
    Дано посетитель открыл страницу "Линия"
    И посетитель выбирает вид спорта "Хоккей"
    И в линии отображается 1 событие
    Когда посетитель выбирает вид спорта "Все"
    Тогда в линии отображается 4 события
    И вкладка "Все" выделена как активная

  Сценарий: Вид спорта, по которому нет событий
    Дано посетитель открыл страницу "Линия"
    Когда посетитель выбирает вид спорта "Теннис"
    Тогда отображается сообщение "Нет доступных событий по выбранному виду спорта"
    И в линии отображается 0 событий

  Сценарий: Начавшиеся события не отображаются в линии
    Дано в системе есть событие "Локомотив — Динамо" по виду спорта "Футбол", которое началось 2 ч назад
    Когда посетитель открывает страницу "Линия"
    Тогда в линии отображается 4 события
    И событие "Локомотив — Динамо" отсутствует в линии
```

## 4. Пополнение баланса

Пополнение игрового счёта банковской картой на сумму от 100 до 100 000 ₽. Проверка номера карты по алгоритму Луна, срока действия и CVV, история пополнений с маской карты.

> Чтобы делать ставки,<br>
> как авторизованный пользователь,<br>
> я хочу пополнять игровой баланс банковской картой

Сценарии:

1. Успешное пополнение баланса банковской картой
2. Пополнение на недопустимую сумму (4 примеров)
3. Пополнение с некорректными данными карты (4 примеров)

```gherkin
# language: ru
@deposit
Функция: Пополнение баланса
  Чтобы делать ставки,
  как авторизованный пользователь,
  я хочу пополнять игровой баланс банковской картой

  Предыстория:
    Дано зарегистрирован пользователь "ivan_petrov" с паролем "secret123" и балансом 1000 ₽
    И пользователь вошёл в систему с логином "ivan_petrov" и паролем "secret123"
    И пользователь переходит в раздел "Пополнить"

  Сценарий: Успешное пополнение баланса банковской картой
    Когда пользователь вводит сумму пополнения "500" и данные карты:
      | номер карты   | 4111 1111 1111 1111 |
      | срок действия | 12/30               |
      | CVV           | 123                 |
    И нажимает кнопку "Пополнить баланс"
    Тогда отображается сообщение "Баланс пополнен на 500.00 ₽"
    И баланс пользователя равен "1500.00 ₽"
    И в истории пополнений есть запись на сумму "500.00 ₽" с карты "**** 1111"

  Структура сценария: Пополнение на недопустимую сумму
    Когда пользователь вводит сумму пополнения "<сумма>" и данные карты:
      | номер карты   | 4111 1111 1111 1111 |
      | срок действия | 12/30               |
      | CVV           | 123                 |
    И нажимает кнопку "Пополнить баланс"
    Тогда отображается ошибка "<ошибка>"
    И баланс пользователя равен "1000.00 ₽"
    И история пополнений пуста

    Примеры:
      | сумма  | ошибка                                   |
      | 50     | Минимальная сумма пополнения — 100 ₽     |
      | 150000 | Максимальная сумма пополнения — 100000 ₽ |
      | abc    | Введите корректную сумму                 |
      |        | Введите сумму пополнения                 |

  Структура сценария: Пополнение с некорректными данными карты
    Когда пользователь вводит сумму пополнения "500" и данные карты:
      | номер карты   | <номер карты>   |
      | срок действия | <срок действия> |
      | CVV           | <CVV>           |
    И нажимает кнопку "Пополнить баланс"
    Тогда отображается ошибка "<ошибка>"
    И баланс пользователя равен "1000.00 ₽"
    И история пополнений пуста

    Примеры:
      | номер карты         | срок действия | CVV | ошибка                                |
      | 4111 1111 1111 1112 | 12/30         | 123 | Неверный номер карты                  |
      | 4111 1111 1111 1111 | 01/24         | 123 | Срок действия карты истёк             |
      | 4111 1111 1111 1111 | 13/30         | 123 | Укажите срок действия в формате ММ/ГГ |
      | 4111 1111 1111 1111 | 12/30         | 12  | CVV-код должен состоять из 3 цифр     |
```

## 5. Оформление ставки

Выбор исхода в линии, купон с расчётом возможного выигрыша на лету, ставка от 10 до 50 000 ₽, списание суммы с баланса, раздел «Мои ставки».

> Чтобы получить выигрыш, если угадаю исход матча,<br>
> как авторизованный пользователь,<br>
> я хочу делать ставки на исходы предстоящих событий

Сценарии:

1. Успешное оформление ставки
2. Ставка на сумму больше баланса
3. Ставка на недопустимую сумму (4 примеров)
4. Гость пытается сделать ставку

```gherkin
# language: ru
@bet
Функция: Оформление ставки
  Чтобы получить выигрыш, если угадаю исход матча,
  как авторизованный пользователь,
  я хочу делать ставки на исходы предстоящих событий

  Предыстория:
    Дано в линии есть события:
      | вид спорта | хозяева | гости   | П1   | X    | П2   | начало через, ч |
      | Футбол     | Спартак | ЦСКА    | 2.10 | 3.40 | 3.20 | 5               |
      | Хоккей     | СКА     | Ак Барс | 1.95 | 4.10 | 3.05 | 2               |
    И зарегистрирован пользователь "ivan_petrov" с паролем "secret123" и балансом 1000 ₽

  Сценарий: Успешное оформление ставки
    Дано пользователь вошёл в систему с логином "ivan_petrov" и паролем "secret123"
    Когда пользователь выбирает исход "П1" в событии "Спартак — ЦСКА"
    Тогда открывается страница "Купон"
    И в купоне указано событие "Спартак — ЦСКА", исход "П1" и коэффициент "2.10"
    Когда пользователь вводит сумму ставки "200"
    Тогда возможный выигрыш равен "420.00 ₽"
    Когда пользователь нажимает кнопку "Сделать ставку"
    Тогда открывается страница "Мои ставки"
    И отображается сообщение "Ставка принята"
    И баланс пользователя равен "800.00 ₽"
    И в списке ставок есть ставка:
      | событие           | Спартак — ЦСКА |
      | исход             | П1             |
      | коэффициент       | 2.10           |
      | сумма             | 200.00 ₽       |
      | возможный выигрыш | 420.00 ₽       |
      | статус            | В игре         |

  Сценарий: Ставка на сумму больше баланса
    Дано пользователь вошёл в систему с логином "ivan_petrov" и паролем "secret123"
    Когда пользователь выбирает исход "П2" в событии "СКА — Ак Барс"
    И пользователь вводит сумму ставки "1500"
    И нажимает кнопку "Сделать ставку"
    Тогда отображается ошибка "Недостаточно средств на балансе"
    И посетитель остаётся на странице "Купон"
    И баланс пользователя равен "1000.00 ₽"

  Структура сценария: Ставка на недопустимую сумму
    Дано пользователь вошёл в систему с логином "ivan_petrov" и паролем "secret123"
    Когда пользователь выбирает исход "X" в событии "СКА — Ак Барс"
    И пользователь вводит сумму ставки "<сумма>"
    И нажимает кнопку "Сделать ставку"
    Тогда отображается ошибка "<ошибка>"
    И баланс пользователя равен "1000.00 ₽"

    Примеры:
      | сумма | ошибка                              |
      | 5     | Минимальная сумма ставки — 10 ₽     |
      | 60000 | Максимальная сумма ставки — 50000 ₽ |
      | сто   | Введите корректную сумму            |
      |       | Введите сумму ставки                |

  Сценарий: Гость пытается сделать ставку
    Дано посетитель открыл страницу "Линия"
    Когда посетитель выбирает исход "X" в событии "Спартак — ЦСКА"
    Тогда открывается страница "Вход"
    Когда пользователь входит с логином "ivan_petrov" и паролем "secret123"
    Тогда открывается страница "Купон"
    И в купоне указано событие "Спартак — ЦСКА", исход "X" и коэффициент "3.40"
```
